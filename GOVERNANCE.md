# Project Governance

img-man uses a lightweight **maintainer-led** governance model.

## Roles

- **Maintainers** — review and merge PRs, cut releases, and set technical
  direction. Listed in CODEOWNERS.
- **Contributors** — anyone who submits issues, PRs, or documentation.

## Decision making

- Routine changes: lazy consensus. A PR may merge once it has at least one
  maintainer approval and CI is green.
- Significant changes (architecture, public API, license/governance): require
  agreement from a majority of maintainers and an issue documenting the rationale.

## Releases

Releases follow semantic versioning. The community edition and the private SaaS
wrapper track the same core version; the public repo is always the source of
truth for shared code.

## Becoming a maintainer

Sustained, high-quality contributions and review participation can lead to a
maintainer invitation by existing maintainers.

## Code of Conduct

All participation is governed by CODE_OF_CONDUCT.md.
